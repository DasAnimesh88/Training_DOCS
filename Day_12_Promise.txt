Your JavaScript code sends a request to an API.
The API takes some time to process the request.
The API sends data back.
Your code receives the response and continues processing.
Problem with Synchronous Execution

If JavaScript waited synchronously for the API response:

If JavaScript waited synchronously for the API response:

const data = fetch("https://api.example.com/users");
console.log(data);

the browser would be blocked until the server responds.

Send Request
      ↓
WAIT...
WAIT...
WAIT...
Receive Data

During this waiting period:

UI may freeze
User interactions are delayed
Other code cannot proceed
Asynchronous Solution

Instead, JavaScript sends the request and continues executing other code.

This code demonstrates one of the simplest examples of asynchronous behavior in JavaScript.

function hello() {
    console.log("hello");
}

setTimeout(hello, 2000);
What happens?
Step 1: Function is created
function hello() {
    console.log("hello");
}

The function is defined and stored in memory. Nothing is printed yet.

Step 2: setTimeout() is called
setTimeout(hello, 2000);

This tells the browser:

"Wait 2000 milliseconds (2 seconds), then execute the hello function."

JavaScript does not stop here and wait for 2 seconds.

Instead:

setTimeout is registered.
A timer starts in the browser environment (Web APIs).
JavaScript continues executing any remaining code.

A callback is a function that is passed as an argument to another function.

General pattern:

function someFunction(callback) {
    callback();
}

Here, callback is a function received by someFunction.

Understanding the example
function sum(a, b) {
    console.log(a + b);
}

function calculator(a, b, sumCallback) {
    sumCallback(a, b);
}

Callback Hell Example

Let's add more operations:

getData(1, () => {
    getData(2, () => {
        getData(3, () => {
            getData(4, () => {
                getData(5, () => {
                    console.log("All data loaded");
                });
            });
        });
    });
});

Notice the pyramid shape:

getData(1, () => {
    getData(2, () => {
        getData(3, () => {
            getData(4, () => {
                getData(5, () => {
                    ...
                });
            });
        });
    });
});

This is Callback Hell (Pyramid of Doom).

promise came to resolve the issue of call back hell 

 Think of a Promise as an online order on Amazon.
When you place an order, Amazon doesn't give you the package immediately.

Instead, Amazon says:

"I promise I'll either deliver your package or tell you why I couldn't."

Similarly in JavaScript:

let orderPromise = new Promise((resolve, reject) => {
    // order processing
});

There are 3 states of a Promise.

1. Pending (Order Placed)

You place an order.

Order Status:
Pending

Amazon is checking:

Is the item in stock?
Is payment successful?
Is delivery available?

The result is not known yet.

Promise state:

Pending
2. Fulfilled / Resolved (Order Delivered Successfully)

Suppose everything goes well.

Order Placed
    ↓
Packed
    ↓
Shipped
    ↓
Delivered

Amazon fulfills its promise.

Promise state:

Fulfilled

JavaScript:

resolve("Your order has been delivered");

function getData(dataId) {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            console.log("data", dataId);
            resolve("success");
        }, 2000);
    });
}

getData(1)
    .then(() => getData(2))
    .then(() => getData(3))
    .then(() => {
        console.log("done");
    })
    .catch((err) => {
        console.log(err);
    });

async function getAllData() {
    await getData(1);
    await getData(2);
    await getData(3);

    console.log("done");
}
