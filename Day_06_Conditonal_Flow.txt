What is the difference between if/else and ternary operator?
  ANS: Both achieve conditional branching.
       if/else is a STATEMENT — can execute multiple lines, use loops, etc.
       Ternary (? :) is an EXPRESSION — returns a value, must be a single
       expression on each side. Use ternary only for simple, readable cases.
       Nested ternary is hard to read — prefer if/else for complex logic.

       ===========================================

 What happens if you use = instead of === in an if condition?
  ANS: if (x = 5) is an ASSIGNMENT, not a comparison. It sets x to 5 and then
       the condition evaluates the result (5), which is truthy — so the block
       always runs. This is a common bug. Some linters flag it.
       Always use === for comparison inside conditions.

/*
  switch is used when you compare ONE VARIABLE against MULTIPLE EXACT VALUES.
  It uses STRICT EQUALITY (===) internally.

  SYNTAX:
  -------
  switch (expression) {
    case value1:
      // code
      break;        // ← CRUCIAL! prevents fall-through
    case value2:
      // code
      break;
    default:
      // runs if no case matches (like else)
  }

  KEY CONCEPTS:
  - break exits the switch block — without it, execution FALLS THROUGH to next case
  - default is optional and can be placed anywhere (convention: at the end)
  - switch uses ===, so "1" !== 1
  - Multiple cases can share the same block (intentional fall-through)
*/

// --- Basic switch ---
let day = 3;
let dayName;
switch (day) {
  case 1: dayName = "Monday";    break;
  case 2: dayName = "Tuesday";   break;
  case 3: dayName = "Wednesday"; break;   // ← matches
  case 4: dayName = "Thursday";  break;
  case 5: dayName = "Friday";    break;
  case 6: dayName = "Saturday";  break;
  case 7: dayName = "Sunday";    break;
  default: dayName = "Invalid";
}
console.log(dayName);   // Wednesday



===================================================================
When break is MISSING, JS continues executing the NEXT case's code
  even if its condition doesn't match — this is "fall-through".
  This is a very common BUG if unintentional.

let status = 2;
console.log("\n--- Fall-through demo (BUG): ---");
switch (status) {
  case 1:
    console.log("Case 1");
    // NO BREAK — falls through!
  case 2:
    console.log("Case 2");   // runs
    // NO BREAK — falls through!
  case 3:
    console.log("Case 3");   // ALSO runs! (fall-through bug)
    break;
  case 4:
    console.log("Case 4");
}
// Output: Case 2, Case 3

 A LOOP repeats a block of code while a condition is true.

 ──────────────┬────────────────────────────────────────────────────┐
  │  Loop Type   │  Best Used For                                     │
  ├──────────────┼────────────────────────────────────────────────────┤
  │ for          │ Known number of iterations, counter-based           │
  │ while        │ Unknown iterations — loop until condition is false  │
  │ do...while   │ Like while but ALWAYS runs at least ONCE            │
  │ for...in     │ Iterate over OBJECT KEYS (enumerable properties)    │
  │ for...of     │ Iterate over ITERABLE VALUES (array, string, etc.)  

===================================================================================

// ─────────────────────────────────
// 3A. for Loop
// ─────────────────────────────────
/*
  SYNTAX: for (initialization; condition; incrememnet/decrement) { body }

  Three parts in the parentheses:
  1. initialization — runs ONCE before the loop starts  (let i = 0)
  2. condition      — checked BEFORE each iteration     (i < 5)
  3. update         — runs AFTER each iteration         (i++)

  Execution order: init → [check condition → body → update] → repeat
*/

/*

What is the difference between for...in and for...of?
  ANS: for...in iterates over KEYS (property names) of an object.
       for...of iterates over ITERABLE VALUES (array elements, string chars, etc.)
       for...in works on objects but is NOT suitable for arrays (can include
       prototype props). for...of requires an iterable — plain objects won't work.
       Rule of thumb: use for...of for arrays/strings, for...in for objects.

===================================================================

Can you use for...of on a string?
  ANS: Yes! Strings are iterable in JavaScript. for...of iterates over each
       character: for (let char of "hello") correctly yields "h","e","l","l","o".
       This correctly handles multi-byte Unicode characters (unlike str[i]).

for...in iterates over:
     a) Array values   b) Object keys   c) String characters   d) Set values

for...of works on:
     a) Only arrays          b) Only objects
     c) All iterables        d) Only strings

function validateLoginForm(username, password) {
  let errors = [];
  if (!username || username.trim() === "") {
    errors.push("Username is required");
  } else if (username.length < 3) {
    errors.push("Username must be at least 3 characters");
  }
  if (!password || password.trim() === "") {
    errors.push("Password is required");
  } else if (password.length < 8) {
    errors.push("Password must be at least 8 characters");
  } else if (!/[A-Z]/.test(password)) {
    errors.push("Password must contain at least one uppercase letter");
  } else if (!/[0-9]/.test(password)) {
    errors.push("Password must contain at least one digit");
  }
  return errors.length === 0
    ? { valid: true, message: "Form is valid" }
    : { valid: false, errors };
}

console.log(validateLoginForm("", ""));
// { valid: false, errors: ['Username is required', 'Password is required'] }
console.log(validateLoginForm("Al", "hello"));
// { valid: false, errors: ['Username must be at least 3 chars', 'Password too short'] }
console.log(validateLoginForm("Animesh", "Playwright1"));
// { valid: true, message: 'Form is valid' }

// SCENARIO 2: Retry Logic with while Loop
// Real-world: Playwright test retry for flaky elements
// ─────────────────────────────────
console.log("\n--- Scenario 2: Retry Logic ---");

function simulateRetry(taskName, maxRetries = 3) {
  let attempt = 0;
  let success = false;
  while (attempt < maxRetries && !success) {
    attempt++;
    // Simulate: fails first 2 times, succeeds on 3rd
    success = attempt >= 3;
    console.log(`[${taskName}] Attempt ${attempt}: ${success ? "SUCCESS ✅" : "FAILED ❌ — retrying"}`);
  }
  if (!success) console.log(`[${taskName}] All ${maxRetries} attempts failed`);
  return success;
}
